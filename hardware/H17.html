01

H17.01

一条 MMA 的逻辑计算

#

M×N×K 描述的是线程数，还是一次矩阵计算？

最小状态
A、B、C/D的形状，数据类型和一次逻辑MMA。
变化规则
每个D[i,j]从C[i,j]加上K个乘积。

MMA的M×N×K定义了A为M×K、B为K×N、C和D为M×N，逻辑计算是D=A×B+C。常见的浮点FLOP记法把一次乘和一次加记为2次运算，所以一条普通dense逻辑MMA约对应2MNK FLOPs。

这些维度不等于物理乘法器数量，也不规定结果在一个周期内全部完成。指令的支持形状、类型和内部执行方式依赖架构；PTX指令到SASS也需核对。用MMA次数估算算量前，先确认家族与计数粒度。

具体例子

m16n8k16对应16×8个输出，每个累加16项，按乘加计2次得到4096 FLOPs，而不是4096个线程。

先预测改变K会改变逻辑工作量，但不能仅据此预测硬件周期。

容易混淆

把逻辑指令tile直接画成等规模的物理硬件阵列。

检验理解同一个MMA形状换成更低精度后，逻辑FLOPs是否自动翻倍？

不自动改变；逻辑矩阵运算量由形状决定，硬件吞吐上限和存储字节可能变化。

02

H17.02

collective 指令的参与线程

#

为什么不能让warp中的几个lane单独执行 mma.sync？

最小状态
warp参与集合、指令参数一致性与有效数据mask。
变化规则
完整collective发起MMA；有效性通过输入填充和输出存储管理。

warp级mma.sync是collective操作：参与warp的线程按同一指令共同提供fragment并接收结果，不能把它理解成32次彼此独立的标量调用。PTX的sync/aligned约束要求相应线程一致执行，分支或提前退出必须满足指令契约。

尾块有无效矩阵元素时，通常保持collective参与，先把越界输入置零并限制最终写回，而不是只让“有有效输出”的lane调用MMA。WGMMA的参与范围扩大到warpgroup；tcgen05则有不同的单线程发起语义，不可套同一规则。

具体例子

一个tile只剩3列有效输出：所有MMA参与线程仍协作，B的无效列补零，写回时只存有效3列。

先预测保留完整参与后结果可正确，但边界tile会执行额外无用算量。

容易混淆

对mma.sync按lane ID做分支，认为未参与lane只会少算自己的元素。

检验理解为什么屏蔽输出store通常比屏蔽MMA参与线程更安全？

store可按有效地址独立predication，MMA则需要规定的完整collective参与。

03

H17.03

matrix fragment 在线程间的分布

#

fragment 是矩阵的一块连续小矩形吗？

最小状态
lane ID、寄存器槽、逻辑矩阵坐标映射。
变化规则
按规定layout把元素分发到fragment，再由collective消费。

fragment是某个线程持有的MMA操作数寄存器集合，矩阵元素到lane和寄存器槽的分布由指令规定。一个线程可能持有不连续行列中的元素；把fragment当作普通row-major数组会把逻辑坐标和存储槽混淆。

低级mma的布局可按PTX图表逐一推导，CuTe把线程和值到坐标的映射编码为layout。高层WMMA的fragment内部布局则不应被当成跨架构ABI。调试时给矩阵元素写入可识别编号，跟踪搬运与计算各阶段的坐标更可靠。

具体例子

用A[i,j]=100i+j标记数据，验证lane0的各寄存器对应哪些坐标，再对照实际mma形状的PTX fragment图。

先预测布局错误可能产生稳定但错误的结果，不能用“重复运行一致”验证正确。

容易混淆

看到每个线程4个FP32累加器，就假设它负责连续4个输出列。

检验理解换一个MMA shape后，旧的fragment索引逻辑还能直接复用吗？

不能保证。线程/值到矩阵坐标的映射可能随形状和类型改变。

04

H17.04

操作数搬运与布局要求

#

Tensor Core 很快，为什么供数仍是 kernel 的主要工作？

最小状态
global tile、shared tile、fragment和复用次数。
变化规则
数据必须完成对应搬运和同步后，才能作为MMA操作数。

算术指令只接受规定位置和布局的操作数。warp级mma通常读取寄存器fragment，输入常先从global进入shared，再通过ldmatrix或其他load装入寄存器；每一级都需要正确的地址、对齐和布局变换。

因此一次GEMM tile的成本不仅是MMA，还包括global搬运、shared读写、地址计算、同步以及epilogue。优化shared布局可减轻bank冲突；增加复用可减少global读取。Hopper/SM100的descriptor操作数路径不同，不能机械套用这一搬运链。

具体例子

同样的16×8×16计算，若每次都重新从global加载A/B，可能远慢于让寄存器或shared中的tile参与多次MMA。

先预测提高有效复用或减少供数冲突，可在MMA数量不变时缩短总时间。

容易混淆

看到Tensor Core峰值高，就认为减半数据类型必然让整个kernel翻倍。

检验理解改shared布局后MMA次数不变却变快，说明什么？

供数或布局开销可能被降低，而不是逻辑计算量发生变化。

05

H17.05

accumulator 依赖链

#

连续对同一 accumulator 做MMA会形成怎样的依赖？

最小状态
累加器依赖关系、结果可用性、资源容量。
变化规则
只在输入依赖满足时推进相应链；不同链可交错提供工作。

D=A×B+D把上一轮累加结果作为下一轮输入，形成真实数据依赖。若下一次操作必须等待该结果可用，单链可能无法持续覆盖执行延迟；交错多个互不相关的输出tile可增加指令级并行性。

但独立累加器需要更多寄存器或TMEM，以及更多供数与最终写回。增加链数可能降低block驻留，或让供数路径先饱和。异步MMA的提交顺序与等待规则也不同，应按指令家族分析，不能模拟成任意乱序执行。

具体例子

顺序C0+=A0B0、C0+=A1B1是单链；交错C0+=A0B0、C1+=A2B2、C0+=A1B1可在程序顺序内提供独立工作。

先预测依赖受限时少量独立链有益，收益不会无限线性增长。

容易混淆

把更多累加器理解成硬件自动跳过前面的依赖指令乱序执行。

检验理解增加独立链到4条后性能不再涨，最先查什么？

查Tensor吞吐、供数、寄存器/驻留与发射资源，确定新的瓶颈。

06

H17.06

指令形状与有效计算利用率

#

Tensor pipeline 接近满载，为什么有效算力仍可能很低？

最小状态
应用M/N/K、指令tile和边界有效区域。
变化规则
向tile尺寸扩展再计算；只将有效区域计入应用算量。

硬件执行的是指令tile，不是应用的任意尺寸。矩阵边界不整除tile时，填充区域也可能占据MMA计算资源；掩码只禁止无效输出写回，并不会自动将这部分矩阵乘法成本归零。

因此要同时区分执行FLOPs与有用FLOPs。前者描述硬件处理了多少指令工作，后者只计应用所需元素。大tile减少循环和发射开销，却可能增加边界浪费及资源用量；小batch、瘦矩阵尤其需要比较这两方面。

具体例子

8×8×16问题若用16×8×16逻辑tile覆盖，M方向有一半输出无效；即使Tensor路径忙碌，有用FLOPs仍只有执行量的一半。

先预测形状不匹配越严重，硬件利用率与有用算力的差距越可能扩大。

容易混淆

把NCU Tensor利用率当成端到端模型MFU。

检验理解有效FLOPs不变、执行FLOPs下降而时间下降，是不是算力退化？

不是，通常说明减少了填充或冗余计算，用更少工作完成同一任务。

07

H17.07

数据类型与累加精度

#

FP16输入、FP32累加是否等价于完整FP32 GEMM？

最小状态
输入格式、累加格式、数值范围与归约长度。
变化规则
先形成可表示输入，再按目标MMA规则乘加和累积。

输入表示和累加表示是两件事。把FP32数据转换为FP16或BF16时已经舍弃部分信息；使用FP32累加能减少累加阶段的舍入影响，却无法恢复输入转换丢失的位。不同格式的动态范围与有效精度也不同。

MMA的乘积、累加和舍入细节受指令类型与规范约束，误差还与K长度、数值分布和求和次序相关。评估时应同时报告绝对/相对误差和任务指标；某篇微基准观察不能外推为所有代际的完整数值契约。

具体例子

两个接近但在FP16中量化为同一个值的FP32输入，即使用FP32 accumulator，也无法保留它们原始差异。

先预测低精度输入的差异不会被高精度累加自动恢复。

容易混淆

把“FP32 accumulation”简写为“没有精度损失”。

检验理解增加K后误差变大，是否一定由输入量化造成？

不一定，还可能涉及累加舍入、抵消、溢出和计算次序，需分离实验。

08

H17.08

结构化稀疏及元数据

#

结构化稀疏的“零”为什么还需要元数据？

最小状态
压缩值、结构约束、元数据索引和原始K维位置。
变化规则
按metadata把保留元素映射到正确乘积位置，省略规定的零贡献。

稀疏MMA使用规定的局部结构，把允许保留的非零元素压紧，并用元数据说明它们在原稠密位置中的索引。例如某些FP16/BF16路径采用每4个元素保留2个的结构，硬件依此将压缩值和B的正确位置配对。

稀疏模式与粒度取决于指令家族、类型和形状，不能把所有低精度稀疏都称为2:4。任意50%零也不等价于满足结构；元数据构建、压缩、精度损失以及shape限制都必须算入部署成本，峰值倍数不是端到端加速保证。

具体例子

一组[0,a,0,b]可存[a,b]及位置1、3；若只保留[a,b]而丢掉位置，无法知道应与B的哪两行相乘。

先预测符合结构可减少规定的工作，但压缩和外围开销仍决定最终收益。

容易混淆

把随机一半元素为零的普通dense数组直接交给sparse MMA。

检验理解每4个元素中有3个非零，能否无损压成2:4格式？

一般不能；必须改变数值、重排算法或选择其他表示。

OBSERVE, THEN EXPLAIN

如何在工具里观察？

以下是核对方向，不是已经采集的测量结果。先在目标 GPU 与 NCU 版本中查询名称和支持范围：

ncu --list-sections
ncu --query-metrics

sm__pipe_tensor_cycles_active.avg.pct_of_peak_sustained_active

在提供此指标的GPU上，比较Tensor流水线活跃程度相对其active-cycle峰值的比例；avg聚合SM实例。

它不是模型MFU，也不扣除padding和无用矩阵元素；架构可能有其他tensor/tc路径，必须query支持情况。

[5]

ComputeWorkloadAnalysis / InstructionStats（sections）

确认实际MMA家族和执行路径，结合tile形状计算每次逻辑操作的工作量。

WGMMA与tcgen05的warp级计数粒度不同；不能直接把所有MMA opcode计数相加再乘同一个系数。

[4]

NCU 的 SM / SMSP、sum / avg、active / elapsed 与采样口径不可混用。若文档或设备没有公开对应计数器，就通过受控对照约束解释，不把间接变化写成硬件内部的直接读数。

ONE VARIABLE, ONE HYPOTHESIS

相同算量，不同累加器链（实验设计，未执行）

只改变

在同一GPU和相同MMA类型/形状下，对比一个累加器链与交错的多个独立累加器链；总MMA次数固定。

预计现象

依赖受限时，多链可能提高吞吐；超过资源容量后收益会停止，额外寄存器还可能降低驻留。

记录什么

检查最终SASS与寄存器数；记录正确性误差、CUDA event时间、Tensor流水线及occupancy；另记录边界padding的有效FLOPs。

排除干扰

编译器重排、指令被消除、不同累加顺序的舍入、SM时钟、供数瓶颈和过短计时窗口。

这是可复现实验设计；本页未运行真实 GPU 或完整 Accel-Sim，也未报告实机性能数据。
